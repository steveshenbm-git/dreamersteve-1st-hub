# 外贸客户工作流 Beta 实施计划

## 范围

在现有 `ft-customer-dev` 分支完成源码、模板和本地验证；不新建分支，不提交，不推送，不安装，不改缓存，不运行真实客户采集或发送。

## 实施顺序

1. 先新增契约测试，证明当前源码缺少协调插件、六页工作簿和三段式候选采集接口。
2. 用插件脚手架建立 `foreign-trade-workflow-director`，补齐技能说明、接口合同、入口配置和市场清单。
3. 用工作簿工具生成六页业务前台模板；先做结构检查，再渲染关键区域检查可读性。
4. 修改 `industry-application-map-builder`：明确机器后台属性、业务前台只读投影和过期事件交接。
5. 修改 `foreign-trade-customer-development`：保留 `candidate_scan` 兼容入口，新增任务导出、批次接收、独立复核三个阶段。
6. 修改 `foreign-trade-customer-operations`：接受协调器交接，向业务前台回传草稿/跟进/风险状态，但不写实际发送事实。
7. 运行新增测试与三个现有插件的回归测试，检查工作簿公式和结构错误。
8. 复核 `git diff`，确保只含本轮设计、插件、技能、测试和模板；交付未提交、未安装状态。

## 失败基线

新增测试应先因以下缺口失败：

- `foreign-trade-workflow-director` 不存在；
- `salesperson-foreign-trade-workbench.xlsx` 不存在；
- 六个业务页不存在；
- 三个专业技能尚未声明与业务前台/协调器的受控交接；
- 客户开发尚未把采集任务、原始批次和复核拆成可追溯阶段。

失败原因必须与上述缺口一致，不能用语法错误或无关依赖失败冒充基线。

## 完成证据

- 新旧契约测试结果；
- 插件清单与 manifest 解析结果；
- 工作簿重开后的工作表、字段、验证、公式错误扫描和关键区域渲染结果；
- 最终变更文件清单和未授权动作确认。

真实业务采集质量、业务员实际易用性和安装后技能触发属于后续实测，不在本地静态检查中宣称通过。
