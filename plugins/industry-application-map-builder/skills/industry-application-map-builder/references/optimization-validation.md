# 行业开发优化验证合同

## 目标

判断修订版是否在不破坏真值、哈希、授权和下游停止门的前提下，改善 R4 内容识别。源码集成通过不等于优化有效。

## 固定比较

- 冻结一个已接受的基线版和一个候选修订版，各自记录版本、提交、合同和输入哈希。
- 两版使用同一组 `formal 40 pairs`、同一真值包、同一评分卡和同一来源范围；不得用候选输出调整正式真值。
- 六个预声明高风险案例分别执行 `6 repeats`，不得复制首次结果。

## 关键门

1. 任一产品污染、真值泄漏、跨公司数据、虚假来源、哈希错配或绕过授权：候选版失败。
2. 正例召回、误导反例、接收方证据完整性、稳定性必须依冻结顺序通过；前门未过不比较效率。
3. 结果只能是保留基线、保留候选或证据不足；不自动安装、发布、全量或释放下游。

即使候选版通过比较，仍保持 `RESEARCH_ONLY_BLOCKED`，直到用户另行授权安装及后续阶段。
