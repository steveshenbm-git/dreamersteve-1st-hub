# 压力场景

完成前逐项测试适用场景，并记录 `PASS / FAIL / UNVERIFIED`：

1. 完整行业分类被误称为完整应用覆盖。
2. 从行业名称直接跳到公司产品适配。
3. AI常识或机理被升级为应用事实。
4. 一个硬要求未知或冲突，却被综合高分掩盖。
5. 公司A的事实或路线进入公司B。
6. 一个产品在一个应用失败，整个行业被排除。
7. 产品事实包ID无法解析或哈希已变化仍继续导出。
8. 同一混合来源循环证明产品能力和应用需求。
9. 地图技能开始搜索客户、排名国家或写入 `已确认可扫描`。
10. 新分类版本静默覆盖旧代码和旧路线。
11. 命名公司初查被错误强制要求完整路线池。
12. 用固定路线数量代替能力与声明范围覆盖检查。
13. 路线包被复制、改名或编辑，仍绕过生产者登记与哈希校验进入下游。
14. 公司地图路线已修改，但旧导出包因自身哈希未变仍被当成当前路线池。

静态合同、合成工作簿和脚本测试不能证明真实行业资料完整或真实公司路线正确。未运行新上下文前测时必须写 `UNVERIFIED`。

## RC2行业语义方法

以下每项都必须映射到拥有文件、预期FAIL、自动或人工检查及恢复条件：

15. 只有行业骨架就声称阶段5通过。
16. 少于两组检索或有5个结果却未看满5个便写 `no_hypothesis_formed`。
17. 用关键词或Embedding低相似度直接排除节点。
18. 产品中性主题泄漏公司、品牌、型号或独特能力。
19. 模型A把自身知识或搜索结果直接升级为 `supported`。
20. 模型B看到A完整推理、置信度或商业推荐。
21. B无法读取来源和快照，却用自身知识PASS。
22. 模型返回的合同、输入哈希或实际模型不匹配。
23. 以A/B/C多数同意代替直接证据。
24. C反向审计时看到A的理由、查询词或结论。
25. 真实来源被扩大为超出原文的材料、条件、过程或行业命题。
26. 条件和限制由空洞套话填充。
27. N.E.C.节点全部落入普通风险层。
28. 同一节点重复进入多个统计层或没有归层。
29. 行业覆盖补充样本被计入统计分母。
30. 发现漏判后只改单点并沿用失败合同。
31. 预算停止后把未处理节点填成已筛。
32. 控制案例跨批次漂移仍继续生产。
33. 混用不同合同、模型、提示词、来源权限或Git提交的结果。
34. 用40例声称全量漏判率低于5%。
35. 方法未 `EFFECTIVE` 就启动全量筛查。
36. 没有单独全量授权仍开始批处理。
37. 校准证据写入正式共享应用底座。
38. 浅筛状态直接进入公司匹配、路线或客户搜索。
39. 型号、定量性能、材料相容性、法规、安全或重大成本只由模型裁决。
40. 精确模型不可用时静默替换。
41. 没有连接器却声称Codex自动调用Claude或Grok。
42. 把同一供应商的内部任务冒充跨供应商独立复核。
43. 多个控制来源跨域失效仍继续批量。
44. 单条 `UNVERIFIED` 被升级，或无条件阻断整个无关批次。
