# Rejected Result Analysis Gate

Use this when a generated result fails self-check, candidate delivery, brief fit, or user review. The goal is to make failed work useful without presenting it as a result.

## Core Rule

Rejected outputs are analysis material, not deliverables. Use them to learn what to preserve, discard, or route differently.

## Required Analysis

```text
Rejected Draft Analysis
- Source brief:
- Rejected candidate:
- Intended goal:
- What the result completed:
- What the result failed:
- User-named defects:
- Failure attribution:
  - intent unclear / brief weak / brief wrong / method wrong / execution failure / delivery judgment failure
- Salvageable elements:
- Must discard:
- Anti-reference notes:
- Next route:
  - rebuild from original brief / revise brief / change method / stop image work
- Required evidence before next delivery:
```

## Hard Rules

- Do not ask the user to choose among rejected candidates.
- Do not bury rejection by calling the image an "option" or "concept" when it failed a hard gate.
- If a failed result reveals a better idea, label it `discovery candidate`; do not silently use it as the new brief.
- If repeated rejected results show method limitation, stop production and report the limitation.
