# Production Lane And Provider Contract

Use this reference before any generated pixels, meaning-changing edit, Magnific formal production, professional retouch, or deterministic final finish. It separates asset identity, provider execution, and cross-skill routing.

## Lane Decision

| Lane | Use for | Provider / method | Allowed result identity |
|---|---|---|---|
| Test | One declared composition, relationship, prompt, or model-behavior hypothesis | Native Codex image generation | `analysis only` |
| Formal | New formal asset, meaning-changing edit, professional retouch, reference-led rebuild | Magnific by default; an alternate formal provider only when explicitly supplied or authorized by the user | raw provider return, then `formal candidate` or `formal revision` only after Imagegen review |
| Deterministic | Exact crop, measured color correction, resize, compression, comparison files, desktop/mobile composites | Deterministic local processing | inherited accepted status or `final export` after the required acceptance gate |

Do not silently switch or promote lanes. A strong test result may inform the next execution hypothesis. Its pixels may be supplied to Magnific only after the user explicitly authorizes that reference use and rejected defects are listed as forbidden carry-over.

If a test output must be preserved, store it only as a Trial under the fixed Jiangyue image output root and keep its status `analysis only`; do not place it in a usable-draft or final archive.

## Provider Readiness

Before Magnific production, verify only the capabilities material to the current subtask:

- account/plan entitlement and remaining credits when exposed;
- current model catalog and requested generation/edit action;
- reference-image and mask support required by the execution package;
- requested output resolution or expansion path;
- result retrieval and local download path;
- access method: MCP or a user-authorized signed-in browser session.

Do not store credentials, cookies, authorization tokens, private account data, or temporary signed download URLs. A plan, credit, connection, action, result-access, or download failure is `external execution blocked`. Keep design and visual-quality states unverified unless actual image evidence exists.

## Model Selection

When the user names an exact Magnific model, preserve it as a method constraint and verify that it is currently available for the required action. Otherwise Imagegen selects from the currently verified catalog based on:

- new generation versus meaning-changing edit or retouch;
- single-reference versus multi-reference control;
- mask/protected-region needs;
- people, product, material, spatial, and text-free image requirements;
- resolution, cost, and attempt-stop constraints;
- ability to preserve the Planner Brief's reality and visual-quality floors.

Do not encode a permanent winner from an old pricing page, comparison, or successful task. Model choice is local to the current attempt and recorded with its verified capability ceiling.

## Provider Return Package

Preserve the raw return before judging it:

```text
Provider Return Package
- Package identifier:
- Provider / access method / model / action:
- Provider return status: returned / blocked / unavailable
- Task or generation ID, if available:
- Credits estimated / actual, if available:
- Prompt and negative-constraint reference:
- Reference and mask inputs:
- Raw provider output:
- Local downloaded source:
- Retrieval or provenance limitation:
```

After `returned`, Imagegen runs Whole-Image Synthesis, reality, visual quality, Intent-Brief-Result, Candidate Delivery, and page-use checks. It then sends one `Imagegen Verdict` to Workflow Director. Magnific completion, a task ID, or a downloaded file alone is not candidate approval.

## Attribution And Route

| Evidence | Imagegen attribution recommendation | Workflow route |
|---|---|---|
| Valid brief, provider output visibly drifts from protected subject, relationship, geometry, or quality | execution/model/package failure | Imagegen revises model, action, prompt, references, mask, or method |
| Provider output satisfies the brief but the brief does not serve the original intent | brief/contract failure | Planner revises the owning decision |
| No usable image evidence because entitlement, credits, access, action, or retrieval failed | external execution blocked | Resolve provider state or request a separately authorized formal-method change |
| Standalone formal image passes but named desktop/mobile composite fails | page-use or deterministic integration failure | Deterministic Imagegen work or page/layout owner; Planner only when the contract itself is wrong |
| Formal result passes the active gates | eligible result | Workflow presents the correctly classified review object |

Workflow Director owns the final cross-skill route. Imagegen owns visual evidence and the attribution recommendation. Planner receives only contract failures, not every generated result.
